# Alsat Safety — состояние проекта

Обновлено: 2026-08-23.

## Цель первой версии

Коммерческий B2B-сайт для предприятий Казахстана: объяснить продукт за 30–60 секунд, показать реалистичный демо-кабинет и доставить заявку владельцу.

## Аудит исходного состояния

- Отдельный репозиторий или опубликованный сайт с точным названием Alsat Safety не найден.
- В общем репозитории alsat.asia есть материалы BIOT/SSAP, но нет выделенного сайта Safety.
- Основной репозиторий содержит множество незакоммиченных и не связанных с задачей изменений. Они не изменялись.
- Переиспользован только общий опыт статической архитектуры и серверного уведомления через Telegram; исходный код общего сайта не копировался.
- В конфигурации существующего репозитория обнаружен секрет в Git remote. Он не переносился и должен быть отозван/заменён владельцем отдельно.
- В части существующих серверных файлов общего сайта также обнаружены значения доступа в коде. Новый модуль использует только переменные среды.

## Архитектура

- Статические HTML/CSS/JS без тяжёлого фреймворка и клиентских зависимостей.
- Cloudflare Pages Function `functions/api/lead.js` для заявок.
- RU: `index.html`; KZ: `kk.html`; структура допускает добавление EN отдельной страницей.
- Кликабельный прототип кабинета: `dashboard.html`, только явно обозначенные демо-данные.
- События воронки попадают в `window.dataLayer` и событие `alsat:analytics`; провайдер аналитики пока не выбран.

## Распределение инструментов

- Работа с кодом и файлами — Harness, если он реально подключён и доступен в текущей сессии.
- Управление браузером и Mac — Codex.
- Проверка внешнего вида — Codex Computer Use.
- Сложное архитектурное ревью — Codex; Claude Code допускается как независимое второе мнение.
- Удалённые команды с телефона — существующий Telegram-пульт.

Перед применением каждого средства необходимо проверить его фактическую доступность. Если Harness или Claude Code не подключены, Codex продолжает работу самостоятельно и не имитирует их использование. Конфигурация Telegram-пульта и удалённого доступа не меняется без отдельной необходимости.

## Принятые решения

- Не строить авторизацию и базу данных до проверки спроса.
- Не обещать аккредитацию, официальный допуск или юридическую силу внутренних сертификатов.
- Успешная отправка формы показывается только после подтверждённого уведомления владельцу.
- При наличии Cloudflare KV заявка сохраняется до отправки, а статус доставки обновляется.
- Canonical временно принят как `https://safety.alsat.asia/`; до публикации требуется подтверждение владельца.

## Безопасность формы

- Серверная allowlist-валидация, ограничения длины, проверка телефона и email/Telegram.
- Honeypot и минимальное время заполнения.
- Rate limit: пять запросов в час на IP; для нескольких инстансов рекомендуется `LEADS_KV`.
- Проверка Origin, CSP и защитные HTTP-заголовки.
- Секреты отсутствуют в HTML, JavaScript и репозитории проекта.

## Официальные источники

- Трудовой кодекс Республики Казахстан: https://adilet.zan.kz/rus/docs/K1500000414
- Правила и сроки обучения, инструктирования и проверки знаний № 1019: https://www.adilet.zan.kz/rus/docs/V1500012665

Юридические формулировки являются общим описанием продукта, а не юридической консультацией.

## Известные ограничения и следующий шаг

- Реальная доставка не проверяется без временного безопасного окружения с Telegram-переменными.
- Аналитика подготовлена событиями, но не отправляется внешнему провайдеру до его выбора и настройки согласия.
- Демо-кабинет не хранит изменения и не является рабочим LMS.
- До деплоя: подтвердить публичный URL, задать secrets и KV в хостинге, провести одну тестовую заявку, затем проверить событие в Telegram.
